# 実写のようなリアルさへの AI 連携の検証(2026-11)

利用者指示「最新のAI情報をかき集め、blenderMCPやMuse等への連携・利用で実写のようなリアルさを実現できるかを検証して。
動作が重くなることやスマホでの動作は考えなくて良い」への調査と実証の記録。
出典の URL は利用者への報告(会話)に、測った値とやり方はこのファイルに残す。

## 1. 結論の要約

- **利用者の言う「Muse」= Meta の Muse(Image/Video/エージェント)**。話題の「PLATEAU で実写の街並み」は
  「PLATEAU→Blender の静止画→Muse Image で実写化→Muse Video で10秒動画」の流れ(§1b)。**このビューアでは、
  素の PLATEAU からでなくビューアの絵(計画反映済み)を Muse に渡すのが正しい使い方**=下の (b) の最有力の実装。
- **「ビューアの画面そのもの」を実写にする一段の決め手は、2026-11 時点では無い**。近いのは
  (a) **書き出し→Blender(Cycles)で物理ベースの光にする**(今回この環境で実証。確実・一貫・無料だが「きれいな CG」まで)、
  (b) **その絵を拡散モデル(img2img / vid2vid)で実写風に変換する**(見た目は最も実写に近づくが、形が揺れる・静止画向き・API 代)。
  二段重ね (a)→(b) が最も堅い。
- **BlenderMCP は「接続の道具」**であって画質の機能ではない。利用者の PC の Blender に addon を入れ、Claude が
  対話的にシーンを組む・直す・レンダリングする。今回ヘッドレスで実証した「GLB→Cycles」の道をそのまま対話で運用できる。
- **Muse は 2 つあるがどちらも当てはまらない**。Unity Muse は 2026 に廃止され「Unity AI」(Unity エディタ内の
  エージェント)へ移行=Unity に移植しない限り無関係。Microsoft Muse(WHAM)はゲームプレイ映像の生成研究
  (Bleeding Edge の 300×180px 映像で学習)で、既存 3D シーンの実写化には使えない。

## 1b. Meta の Muse(利用者の意図はこれ。2026-11-16 追補)

当初の調査で「Muse」を Unity Muse・Microsoft Muse と解したのは**取り違え**。利用者の意図は **Meta(Meta Superintelligence
Labs)の Muse シリーズ**:Muse エージェント(クラウド上の専用 PC で作業を代行。日本は 2026-10-23 から)・Muse Spark(LLM。
2026-04〜)・**Muse Image**(画像の生成と編集)・**Muse Video**(静止画→10秒の動画)。2026-11 に日本の X で
「**PLATEAU×Blender×Muse** で実在の街(大阪城・東京駅・兼六園)の空撮風映像」が話題になった。

- **話題の手順**(解説記事の要約):Muse エージェントに日本語で指示 → エージェントが G空間情報センターから PLATEAU を取得し、
  **自分のクラウド PC の Blender に読み込んで**指定の画角の静止画を1枚レンダリング → Muse Image がそれを実写風に →
  利用者が確認 → Muse Video がその静止画を参照して **10秒の動画**に。
- **品質と限界**(記事の指摘):動画の段で**データに無い要素が現れる**・**LOD1 だけの地域は再現が難しい**。
- **提供形態**:日本では Meta AI アプリと meta.ai(Web)。画像生成は無料枠あり(回数上限。具体数は画面で確認)、
  Meta One の Core(月949円)/Premium(月2,900円)で枠が拡大。開発者 API は**1枚 $0.01 の従量課金**(無料枠なし)。
- **このプロジェクトでの使いどころ**:
  1. **話題の手順そのまま(素の PLATEAU)は不向き**。Muse が作るのは「今の街」で、このビューアの価値である
     **計画の反映(高架・駅・駅前広場・放射23号線)が消える**。LOD1 の弱さの指摘もある(ビューアは LOD1 を作り込み済み)。
  2. **推奨:§3 の二段重ねの (b) に Muse を充てる**。ビューアのスクリーンショット(または §3 の Cycles の絵)を
     Muse Image に渡し「この構図・建物・配置のまま実写の写真に」→ 決めカットは Muse Video で10秒動かす。
     入力の形が正確(計画反映済み)なので、話題の例より下絵の素性は良い。
  3. エージェント版 Muse はクラウドの Blender を**会話で**操作する=BlenderMCP の役を Meta 側の PC で果たす代替にもなる
     (GLB を渡せるかは未確認)。
- **この環境では実測できない**(Meta アカウントとアプリ/画面が要る。API も鍵が無い)。入力画像とプロンプトの一式を
  用意したので、利用者の Meta AI アプリで試せる(下の「試し方」)。
- **注意**:生成画像の透かし・商用利用の条件は Meta の現行規約を利用時に確認。公開時は「AI 生成・非公式」を明記。
  PLATEAU 自体は手続き不要・商用可(公式 FAQ)。

### Muse での試し方(利用者向け。所要 数分)
1. Meta AI アプリ(または meta.ai)で Muse に下の画像のどちらかを渡す:
   - ビューアのスクリーンショット(メニューで 航空写真 ON・昼 が無難)
   - §3 の Cycles の絵(光が既に物理的なぶん、実写化が安定しやすいはず=未検証)
2. プロンプト例(静止画):
   「この 3DCG と**同じ構図・同じカメラ・同じ建物の配置のまま**、実写の写真にしてください。晴れた昼の東京の住宅街、
   京王線の高架駅。建物の位置・形・道路・高架は**変えない**。質感(コンクリート・ガラス・アスファルト・街路樹)と
   光だけを写真のリアルさに。人や車を**勝手に足さない**」
3. 良ければ続けて:「この静止画を開始フレームとして、カメラがゆっくり前進する10秒の動画に。構図と建物は変えない」
   (キャラ固定の定石=**元画像をスタートフレームに指定**し keep same composition を強く書く、は街でも同じ)
4. 形が流れたら:構図の文言を増やす・1回で大きく変えず多段で(昼→夕 など)・決めカットだけに使う

## 2. 調査の要約(2026-11)

|---|---|---|---|

| **Blender(Cycles)単体** | パストレーシング(GI・ソフトシャドウ・AgX) | 同上。ヘッドレスは pip の bpy で自動化可(今回実証) | 同上。材質を作り込めば建築ビジュアル級 |
| **Meta Muse(Muse Image/Video/エージェント)** | 画像の実写化・静止画→10秒動画・クラウド PC での Blender 代行(§1b) | ビューアの絵を Muse Image→Muse Video(推奨)。素の PLATEAU からの再現は計画が消えるので不向き | 静止画・短尺では最有力級。データに無い要素が出る・無料枠に上限・API $0.01/枚 |
| **Unity Muse → Unity AI** | Unity エディタ内のアシスタント(2026-05 オープンベータ。クレジット制) | Unity への移植が前提=非現実的 | 対象外(名前違い) |
| **Microsoft Muse(WHAM)** | 学習したゲームの続き映像の生成(研究。Azure/HF に公開) | 無し | 対象外 |
| **静止画 img2img**(Nano Banana Pro=Gemini 3 Pro Image/FLUX+ControlNet depth) | CG の 1 コマを実写風に描き直す(構図・奥行きを保てる) | ビューアのスクリーンショット(+できれば深度)を渡すだけ。**最短で試せる** | 静止画なら最も実写に近い。形の勝手な変更・SynthID 透かし・XLabs の depth 版は非商用 |
| **動画 vid2vid**(RealMaster=Wan2.2 の IC-LoRA・REGEN・zero-shot 構造保持) | レンダリング映像→実写風映像(GTA-V 等で実証) | capture.js の連番→変換。**研究段階**(公開実装・重み要確認・要 GPU) | 論文レベルでは有望。時間一貫性が課題。REGEN は GAN でリアルタイム寄り |
| **動画生成 I2V**(Veo 3.1/Sora 2/Wan 2.5) | 1 枚の絵+プロンプト→数秒〜12 秒の実写風動画 | ビューアの 1 コマを種に。長尺・正確な線形の再現は不可 | 単発カットの見栄えは高い。構図が流れる・有料 |
| **3D Gaussian Splatting**(three.js r186 ネイティブ/Spark) | 実写の取り込み表示(写真由来のスプラット) | 実写パーツ(駅前の実写スキャン等)を Three.js シーンに併置 | 「実写そのもの」だが現地撮影か点群が要る。計画(未完成の高架)には使えない |
| **Marble(World Labs)** | 1 枚の画像→歩ける 3DGS 世界(1.1。$20/月〜) | ビューアの絵→雰囲気のある周辺世界。精密な再現は不可 | 屋外・広域は弱いとの評 |
| **3D 資産生成**(Hunyuan3D・TRELLIS.2・Meshy 6・Tripo・Rodin) | 文・画像→PBR テクスチャ付きメッシュ | 添景(車・ベンチ・植栽)の差し替え、PBR 材質の供給 | 資産単位の底上げ。街全体には不向き |

## 3. この環境での実証(2026-11-16)

**やったこと**:ビューア(明大前の駅前街路の視点)→ GLTFExporter(r128)で GLB(54MB)→ pip の bpy 5.0.1
(ヘッドレス Blender)→ Cycles CPU でレンダリング → Three.js の同視点と比較。

- 道具(このフォルダ):
  - `export_glb.js` … ページを Playwright で開き、視点の周り R=240m の Mesh と、インスタンス(まくらぎ・木・ホームドアの戸・車 等)を
    **個々のインスタンスの位置で選んで**頂点へ焼き込み、GLB と比較用 PNG・視点の meta.json を書く。
    three r128 の GLTFExporter.js は `npm pack three@0.128.0` から取り出す(ネットワークの制限で CDN 直は 403)
  - `render_cycles.py` … GLB を import、太陽(ビューアの昼の向き (2400,3200,1600))+Nishita 系の空
    (Blender 5.0 では sky_type='MULTIPLE_SCATTERING' に改名)、視点を meta.json から再現(three (x,y,z)→Blender (x,−z,y)、
    縦 FOV 46°)、AgX・denoise(OIDN)。環境変数 SUN/SKY/EXPO で明るさ(採用値 SUN=6, SKY=0.055, EXPO=0.2)
- 結果:480×270・24 サンプル=約 13 秒、1280×720・160 サンプル(適応+デノイズ)=数分(4 コア CPU)。
  GI(高架下の影の溜まり)・ソフトシャドウ・木や柵の落ち影・AgX の階調が付き、「均一な昼」の Three.js より写真的な光になる。
- **躓きと直し**(作り直すときの注意):
  - MG 系ジオメトリの `uv` は一部の面にしか無く頂点数が合わない → そのまま書くと Blender の glTF import が
    `IndexError`(uvs[indices])で落ちる。**頂点数が position と合わない属性は書き出し前に外す**
  - InstancedMesh を「形の外接球が視点の近くにあるか」で選ぶ → 近くの木 `CITY.treeNear` は形の外接球が原点のままで
    **全部落ちる**(まとまりの木では近くの木が scale 0=二重に消える)。**個々のインスタンスの行列の平行移動で選ぶ**
  - Blender の保存先は**絶対パス**(相対は「cannot save」)
  - bpy の Python は 3.11 限定(この環境の python3.11 と一致。pip install bpy==5.0.1 で入る。ヘッドレスでも Cycles CPU は動く。
    EEVEE/Workbench は GPU(libEGL)が無く動かない)
- **運べない物(今の作りの限界)**=このまま Blender に持ち込んでも白いままの物:
  - **シェーダで塗っている物**:車両の帯・窓・扉(K8/K9/K10/K30 の塗り分け)、建物の外装の窓・店先(bwFacade)、
    航空写真。glTF には乗らない → 建物は無地の箱、車両は下地色になる。**列車は書き出しから除外した**
  - 電線(LineSegments)は太さが無く Cycles では見えない(カーブ化が要る)
  - 人(部品を頂点属性で選ぶ)は焼けない → 除外
  - 本気で Blender 側をリアルにするなら、**シェーダの塗りをテクスチャに焼く**(車両=側面・前面を正射影で
    canvas に描いて UV を貼る/建物=bwFacade を面ごとにテクスチャへ)工程を足すのが次の一歩

## 4. 推奨の道筋(段階)

1. **すぐ(数分・追加実装なし)**:ビューアのスクリーンショットを **Nano Banana Pro(Gemini)に img2img**
   「この CG を同じ構図・同じ建物・同じ時刻の実写の写真に」→ 静止画の"実写化"の上限を体感できる。
   形が変わる・透かしが入る点だけ注意(公開時は AI 生成と明記)
2. **短期(半日)**:今回の `export_glb.js`→`render_cycles.py` の道を **BlenderMCP**(利用者の PC)に載せ替え、
   会話で照明・材質・構図を詰める。シェーダ塗りのテクスチャ焼き(§3 の最後)を足すと Cycles 単体で建築ビジュアル級
3. **中期(数日〜)**:capture.js の連番に **vid2vid(RealMaster 系/Wan2.2 ベース)** を当てる実験(要 GPU。
   研究実装の公開状況を確認してから)。または決めカットだけ **Veo 3.1 / Sora 2 の I2V**
4. **ビューア本体のリアル化**(AI に依らない併走策):WebGPU 版 three への移行+パストレース静止画モード、
   PBR テクスチャ(AI 生成の tileable 素材)への置き換え、3DGS の実写パーツ併置
