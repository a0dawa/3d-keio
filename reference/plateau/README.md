## 取り込んだデータ(2026-10)

- 国土交通省 3D都市モデル(Project PLATEAU)**2025年度** CityGML(v5):渋谷区・杉並区・世田谷区・調布市
  (`assets.cms.plateau.reearth.io` の `131xx_*_pref_2025_citygml_1_op.zip`)。zip 全体(0.44〜1.0GB)は落とさず、
  HTTP の範囲指定で目次を読み、`udx/bldg/` の22メッシュだけを取り出した(合計 1.1GB の GML)。
  区ごとの zip に入っている同じメッシュのファイルは同一(メッシュに全区の建物が入っている)
- `plateau_import.py --min-area 25 --tol 0.5`:帯(駅を結ぶ折れ線から540m)で 31,691棟 → `plateau_bldg.js`(1.5MB)。
  ビューアの帯(|off|≤470・事業区間)と占有域で約2.2万棟を描く
- 許可したドメイン:`www.geospatial.jp`(カタログ)・`assets.cms.plateau.reearth.io`(ファイル)

作り直すとき(年度の更新など):カタログ API(`/ckan/api/3/action/package_search?q=plateau 世田谷区`)で zip の URL を引き、
22メッシュの `udx/bldg/*.gml` を取り出して、
```bash
python3 -I tools/plateau_import.py --html keio_elevated_3d.html --min-area 25 --tol 0.5 \
  --source '国土交通省 3D都市モデル(Project PLATEAU)2025年度 渋谷区・杉並区・世田谷区・調布市' --out plateau_bldg.js <GML…>
```

## 道路(2026-10。`plateau_land.js`)

- 同じ4つの zip の `udx/tran/<3次メッシュ>_tran_6697_op.gml`(22メッシュ・71MB)。範囲指定で取り出す
  (取り出しの道具は `udx/bldg/` の代わりに `udx/tran/` を絞るだけ)。同じメッシュでも区の zip で中身が違うことがある
  (53394512・53394513 は渋谷区と世田谷区で大きさが違った)ので、最初に見つかった区のものを使った(世田谷区→杉並区→渋谷区→調布市の順)
- 中身は `tran:Road` の `lod1MultiSurface`(道路区域の平面形。高さ0)。属性 `tran:function`(Road_function:1=高速自動車国道・
  2=一般国道・3=都道府県道・9020=区市町村道など)、名称(国道20号・都道318号=環七・都道311号=環八・首都高速4号新宿線 …)、
  `uro:sectionType`(1=道路・2=橋梁・3=トンネル・4=交差部)。一部に LOD2(車道・歩道の区分 TrafficArea)もあるが使っていない
- `tools/plateau_land.py`:種別を 0=一般/1=幹線(国道・都道)/2=自動車専用(function 1・名称に「高速」「自動車道」)にまとめ、
  帯(560m)で絞り、0.3m で単純化 → 12,343面・頂点10.8万・0.7MB
  ```bash
  python3 -I tools/plateau_land.py --html keio_elevated_3d.html --out plateau_land.js \
    --source '国土交通省 3D都市モデル(Project PLATEAU)2025年度 渋谷区・杉並区・世田谷区・調布市' --tran <tran の GML…>
  ```
- ビューア(4章):地表の道路は平らな面、自動車専用の橋梁(首都高4号・中央道)は床版+高欄+橋脚。模式の道路(甲州街道・
  旧甲州街道・首都高・交差道路の帯・旧踏切の通り抜け)は描かない(計画の放射23号線だけ残す)。建物・樹木は道路の面に掛けない
- **実データで分かったこと**:模式の「環七」の位置(s≈−364)は実際は中野通り(都道420号)で、環七(都道318号)は s≈606
  (代田橋の手前)。高架の柱が環七の路面に立っていた。`RAW.roads.kan7` を直し、中野通りを足した。さらに線路を横切る
  実際の道路(27か所)には柱を立てない(`ROAD_XING`→`ROAD_SKIP`)。模式の旧踏切(XINGS)の位置は実際の道路と 0〜3m で一致した。
  補助154・128・133・215・216・217号線(立体化)は実データに無い(計画)ので、実データがあるときは描かない

## LOD2(屋根の形。2026-10。`plateau_bldg.js` の lod2b64)

- 建築物の GML のうち `bldg:lod2Solid` を持つ建物(沿線の22メッシュで1,340棟。笹塚・明大前・下高井戸・千歳烏山の駅の周りに多い)は、
  `bldg:boundedBy` の RoofSurface/WallSurface/GroundSurface に `lod2MultiSurface`(標高つきの3次元の面)がある
- `plateau_import.py` が屋根面・壁面の外周を、足跡の1点目からの差(0.1m)と GroundSurface の最も低い標高からの高さ(0.1m)で
  別の2進 `PL2A` に入れる(帯の中で715棟・0.37MB)。足跡+高さ(PLT1)の並びと中身は変わらない
- ビューア:近くの形(400m)で、LOD2 のある建物は足跡の押し出しの代わりに面そのものを描く(3次元の多角形は法線の最も大きい
  成分の軸を落として耳切り。屋根は上向き、壁は建物の重心から外向きに表を向ける)。中・遠の箱は今のまま。描かれるのは547棟

## 取り込みの方法(試作:`tools/plateau_import.py`)

```bash
python3 -I tools/plateau_import.py --html keio_elevated_3d.html --out reference/plateau/bldg.bin reference/plateau/citygml/*.gml
```
- 建物ごとに 足跡(lod0FootPrint → lod0RoofEdge → lod1Solid の底面)・高さ(measuredHeight または lod1Solid の高さ)・
  地上階数を取り、ビューアと同じ射影(HTML の MLAT/MLON・原点=笹塚駅)でワールド座標にする
- 駅の並びの外側 600m より遠いもの・15m² 未満は捨て、足跡を 0.3m で単純化し、0.1m 単位の2進(1棟あたり約30〜40バイト)にする
- 外部のデータなので DOCTYPE/ENTITY を含むファイルは読まない
- 合成した CityGML(足跡あり・立体だけ・小さすぎる・範囲外の4棟)で、座標・高さ・面積・捨てる判定を確かめた

## 見積もり

- 棟数:住宅地の密度(2,000〜3,000棟/km²)× 帯の面積(約8km²)= **約1.6万〜2.4万棟**(いまは約1万棟)
- データ量:2進で 0.5〜1.0MB(base64 で 0.7〜1.3MB)。HTML に埋めると 0.36MB → 1.1〜1.7MB。
  **別のファイル(`plateau_bldg.js`)にして script で読む**案なら HTML は増えず、ファイルが無ければ今の模式の街で描ける
  (file:// でも script の読み込みは効く。fetch は効かない)
- 描画:足跡を押し出すと1棟あたり約20三角形 → 40万三角形前後。480m のまとまりごとに結合(呼び出しは今と同じ約20回)し、
  遠いまとまりは箱(外接矩形)に落とす LOD で、⑫の予算(全体俯瞰 79万三角形)に収める見込み

## ビューアに入れるときの手順(次の作業)

1. データを用意(上記)→ `plateau_import.py` で `bldg.bin` を作る
2. HTML:データがあれば、まとまりごとに足跡を押し出して描く(色は階数・用途から)。高架橋・側道・駅・交差道路・
   交差鉄道・河川と重なる建物は、今の占有域 `KEEP` と同じ判定で外す(事業で撤去済みの沿線の建物が古い年度の
   データに残っていても、側道の範囲で落ちる)。樹木は今の模式のまま。夜の窓明かりは足跡の側面に張り直す
3. 検証:⑦(道路・河川・高架下・重なり)を足跡の多角形で測るように広げ、⑫の予算を測り直す
4. 画面に出典を表示する
