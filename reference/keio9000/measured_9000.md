# 京王9000系 寸法の根拠(公表値・写真の実測・推定値の一覧)

`keio_elevated_3d.html` の諸元表 `K9`(9b章)の根拠。8000系(`reference/keio8000_v4/`)は利用者提供の
Blender モデルと編成写真の実測(60px/m)が根拠。9000系は公表値と、利用者提供の写真の実測(前面=3b、
側面=3c。2026-10)が根拠で、写真で測れない所だけ 8000系に寄せて推定した(3)。

値を変えるときは、先にこの表を直してから `K9`(HTML)と検証(`tools/verify_car9.js` ⑭・
`tools/verify_k9render.js` ⑮ の REF)を直す。検証側の基準値は HTML から読まない。

## 2. 公表の説明(形・塗り分けに反映)

- 前頭部は乗務員扉までアイボリー塗装の普通鋼製、スカートも同色(Wikipedia)
- 正側面の腰部に京王レッドと京王ブルーの帯。8000系で窓上(幕板)にあった京王レッドの帯は無い(Wikipedia)
- 扉間に窓2枚、戸袋窓は廃止(2枚1組のサッシュレス1枚下降窓、一部固定)(Wikipedia)
- 前面は8000系に似るがやや直線的。行先表示器は中央扉の上、車号は向かって右の窓の上(ニコニコ大百科)
- 運転台の窓は側面まで回り込むパノラミックウインドウ(鉄道チャンネル)。9705 の写真(3b)では角が写っておらず「前面の中で閉じる」と
  読んだが誤り(利用者指摘):9755 の写真2枚と側面写真(3c)で、左右の前面窓が角の曲面に沿って側面へ回り込むことを確かめた
- 前照灯・尾灯は前面窓の下(マイナビニュース:窓の下・灯火の上にラッピングがある)。前面写真(3b)では青帯の中
- 前面の表示器:更新車は種別・行先ともフルカラー LED(1台にまとめた形で描く)

## 4. 実測で直すときの手順(8000系と同じ要領)

踏切などから撮った**遠近があり支障物のある写真**は `side_photo9.py`(3c の手順:傾きの直し・1次元の射影・床からの高さ。
2026-10 の写真に合わせた画素の範囲を持つので、別の写真では範囲を見直す)。**真横から撮った遠近の小さい編成写真**は
次の `measure_side9.py` で測れる:

1. 編成写真(山側・海側。真横から撮った遠近の小さいもの、1両 1000px 以上)を用意し、側面の実測の道具で測る:
   ```bash
   python3 -I reference/keio9000/measure_side9.py 写真.png --ends 列A 列B --rail 行 --cab left   # 先頭車(運転台が左)
   python3 -I reference/keio9000/measure_side9.py 写真.png --ends 列A 列B --rail 行               # 中間車
   ```
   `--ends` は1両の車体の両端の列(連結面ではなく車体の端。車体長 19.5m で 60px/m に揃える)、`--rail` はレール面の行。
   出力は帯(赤・青)の高さ・側窓と扉窓の下端と上端・窓の並び・扉の中心(扉窓の対の中点)・先頭車のアイボリーの後端を、
   この表の今の値と並べた表(Markdown)。`--out` で 60px/m に直した画像も書く。測った値をこの表に書き足す
2. 前面写真から、ガラス域・灯火・表示器・車号の位置を測る(前面は 2026-10 に実測済み=3b)
3. `K9` と検証の REF(⑭⑮)を直し、`bash tools/verify_all.sh` を通す

**道具の確かめ(2026-10)**:写真はまだ無いので、自分の描画(⑮の側面 60px/m と 45px/m に縮めた写し)に当てて、
描いた値(この表の値)が戻ることを確かめた。帯・窓・扉・アイボリーの後端とも元の画像の1.5画素以内(⑮が毎回確かめる)。
縮めてぼかし雑音を足した写し(45・84px/m)でも同じ。33px/m まで粗くすると扉間の2枚の窓の間の柱(5cm)がぼけて
1枚につながり、窓の下端が帯に寄る(道具が警告を出す)。色の判定は v4 の照合ツールと同じ閾値で、窓は
「ステンレスでもアイボリーでも赤帯でもない所」(窓越しの暗い車内は青みが勝つので青は外さない)。
写真の光の具合でステンレスやアイボリーの判定が外れたら、`masks()` の閾値を見直す。
